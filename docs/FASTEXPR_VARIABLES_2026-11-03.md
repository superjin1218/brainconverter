# FASTEXPR 필드와 계산 변수 · 2026-11-03

기준은 `a37b2cc`의 카탈로그 기반 변환기입니다. 기존 카탈로그·임베딩 검색·자료형 처리·비용 제어를 보존하고 변수 선언과 복합 계산식 처리를 보완합니다. 사용자의 추가 지시에 따라 **실제 BRAIN 접속·로그인·Simulate를 진행하지 않으며, 추가 AI 호출도 하지 않습니다.**

## ROE 코드에서 구분할 것

`roe`는 확보된 필드 목록에 없는 이름입니다. 이를 선언 없이 사용하는 `group_rank(roe, industry)`는 받아들여서는 안 됩니다. 반면 `return_equity`는 제공 카탈로그에 `Return on Equity`로 등록된 계산값 필드입니다. 제공 필드는 별도의 로컬 선언 없이 참조할 수 있습니다.

```text
group_rank(return_equity, industry)
```

제공 필드에 로컬 변수 이름을 붙여 사용한다면 선언이 먼저 있어야 합니다.

```text
roe = return_equity;
group_rank(roe, industry)
```

직접 지표를 계산하는 경우는 실제 순이익·자기자본 등의 입력 필드와 요청한 보고 기간·분모 정의에 맞는 계산식이 필요합니다. 단순히 지표 약어를 원자료 필드인 것처럼 넣지 않습니다. 계산식을 함수 안에 직접 넣는 방식도 유효하며, 이름을 붙였을 때 그 이름의 정의가 필요하다는 뜻입니다.

## 코드 변경

- `DraftCompiler`에 세미콜론으로 구분한 `이름 = 계산식; 마지막 출력식` 처리를 추가합니다. 허용된 표현식 AST만 파싱하며 Python 코드를 실행하지 않습니다.
- 변수는 선언 후에만 참조할 수 있습니다. 중복 정의, 순환/전방 참조, 제공 필드·함수 이름 덮어쓰기, 출력에 쓰이지 않는 선언을 차단합니다. 변수 전개에도 기존 복잡도와 중첩 제한을 적용합니다.
- 제공 필드와 변수 심볼을 별도로 처리합니다. 카탈로그의 필드 존재·자료형·함수 권한 검사를 생략하지 않습니다. 최신 main의 VECTOR 자동 `vec_avg` 정책을 유지하고 변수 재참조 때문에 평균을 중복 적용하지 않습니다.
- `IntentMetric`에 `operation=expression`, `formula`를 추가합니다. 이 경우 field는 실제 입력 필드 하나, reference는 null, window는 1이어야 합니다. 계산 변수는 field/reference 식별자 자리에 넣지 않습니다.
- 복합식은 `calc_1 = 계산식;`으로 선언하고 최종 순위/조건식에서 참조하도록 렌더링합니다. 최종 프로그램을 다시 전개해 원문 숫자·기간과 점수 선호 방향을 검사합니다. 계산식 안에 숨긴 최종 rank·거래 조건은 차단합니다.
- 현재 main에 반영된 비율의 불필요한 `-1` 제거, 인용문 처리, 검색/임베딩 예산과 자동 벡터 집계는 유지합니다. 실제 계정 카탈로그를 정적 예제 목록으로 교체하지 않습니다.
